1. Findings

1.67 Gbit/szero-copy NAT, TCP P4 (B)
606 Mbit/sNAT + flowtable (C, best stack path)
5.21 Gbit/srouted in the ASIC (B)
  • IPv4 NAT: the ASIC rewrites MACs and TTL only, so every NAT packet crosses the CPU port twice.
  • Zero-copy fast path (in-place rewrite, no skb) is the only route near 2 Gbit/s; 2.5 Gbit/s is not reachable.
  • Limits: switch-core clock sets the 1400 B rate; CPU-bound at core 608 (one VPE 97-99 % busy); a second CPU adds nothing.
  • No effect: ring split, NAPI split, SRAM rings, queue thresholds, cache / prefetch variants, GDMA, GRO changes.
  • Final settings: core 608, CPU 1325 (1350 plain kernel only), DDR 662, SRAM 500, LX ~304.
  • Full text: FINDINGS.md. Only controlled data is plotted; old runs are history (section 8).

3. nat vs nat-ft vs zc, by streams and direction

nat = conntrack + masquerade; nat-ft = + nftables software flowtable; zc = this project's in-place fast path.

4. Routed on / off

Routed UDP 1400 B with L3 on: 369.3 kpps (B only; no L3-off UDP row in the controlled set). Only B has the directly-connected L3 offload (300-17); hardware-routed traffic bypasses the CPU firewall and NAT (ROUTING-OFFLOAD.md).
