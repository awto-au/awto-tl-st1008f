ST1008F DRAM review

TL-ST1008F v2 (RTL9303), one DDR3 x16 die, 512 MiB. Theoretical figures from the live controller timings against U-Boot bench measurements, 2026-10-11, heatsink off.

In short

2400 MB/stheoretical peak, DDR3-1200 x16
30–45 nsDRAM read latency, row hit / closed
109–120 nsmeasured per cache-line miss
65 %best measured share of peak (stores, no fill)
  • Plain code is latency-bound: one 32-byte miss at a time, 32 B / 120 ns = 267 MB/s. The DRAM bus sits idle most of the time.
  • Most of each miss is spent outside the DRAM chip: CPU 800 → 1000 MHz cuts it 9 %, DDR 600 → 650 MHz cuts it 2 %.
  • The controller prefetch (off in stock, now on) lifts plain reads +49 % and writes +68 % with 1 GHz.

Why the gap

  • Latency, not bandwidth. The DRAM needs 30–45 ns per read; a miss costs 109–120 ns. The other 65–80 ns sits in the CPU-side bus and controller path, which runs on the CPU clock.
  • Write-allocate doubles write traffic. memset reads every line before writing it. Skipping the read (pref 30) reaches 65 % of peak, so the bus and controller can stream; plain code doesn't feed them.
  • Controller prefetch helps plain code and competes with software prefetch (the pref 0 loop drops 26 % with it on).
  • The DDR clock barely matters: 600 → 650 MHz moved every test by 4 % or less.
  • Linux memcpy already prefetches on this CPU; Linux memset doesn't, so the controller prefetch helps it most.
  • DRAM speed affects only the CPU. Packet switching uses the chip's on-die buffer.

Open decisions and next steps

  • Decide: post the OpenWrt prefetch patch upstream (#53)? It is ready and compile-checked; a boot test via stock U-Boot comes first.
  • Decided: refresh stays at stock. Normal-rate refresh would free about 3.5 % of DRAM time, but access is latency-bound with the bus mostly idle, so the gain is near zero. DDR3 has no readable temperature sensor; the SoC sensor peaked at 75 °C.
  • Research: the unexplained controller bits (ocp0_frq_slower, rbf_f_dis, sync_ocp0_dram) are the only candidates for the 65–80 ns overhead (#52).
  • In progress: DDR above 650 MHz. The chip (Zentel A3T4GF40BBF-HP) is rated DDR3-1866; higher bins need mode-register writes for CL/CWL (#48).
